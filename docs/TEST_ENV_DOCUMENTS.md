# סביבת בדיקה מבודדת — מאגר המסמכים

ענף: `feature/documents-repository`. לא ממוזג ל-main, לא פרוס לייצור.

## הפעלה — פקודה אחת, אפס הגדרות

```powershell
powershell -File scripts/run-docs-test-env.ps1
```

ואז לפתוח: **<http://localhost:3000/#/documents>** (התחברות עם הסיסמה הרגילה).

## מה רץ מאחורי הקלעים

- `scripts/docs-test-server.mjs` (פורט 4000) מריץ את **הפונקציה האמיתית**
  `netlify/functions/documents.js`, כשה-hook `scripts/local-supabase-register.mjs`
  מחליף את supabase-js בתחליף מקומי עמיד (`scripts/local-supabase.mjs`):
  - רשומות: `test-env/db.json` (על הדיסק, שורד הפעלות).
  - קבצים: `test-env/storage/` — נגישים אך ורק דרך כתובות חתומות עם token
    חד-פעמי (העלאה) או מוגבל-זמן (צפייה); גישה ישירה מוחזרת 403,
    כמו bucket פרטי ב-Supabase.
  - אכיפת unique על `file_hash` (קוד 23505) כמו האינדקס במיגרציה.
- Vite (פורט 3000) מגיש את האפליקציה; ה-proxy הקיים של `/api` מפנה לשרת הבדיקה.

## בידוד מהייצור

- הלקוח לא ניגש ל-Supabase ישירות בכלל — הכל דרך `/api`, שמקומית מגיע רק
  לשרת הבדיקה. משתני `VITE_SUPABASE_*` מנוטרלים בתהליך ה-vite שהשרת משיק.
- נתיבי `/api` אחרים (חשבונית ירוקה, מיילים) מוחזרים 404 מכוון בסביבה.
- אין פונקציות מתוזמנות; אין קריאה ל-`.env.local`; שום דבר לא נכתב לענן.

## מפתח הגישה (DOCS_API_KEY)

- סוד אקראי (32 בתים) שנוצר אוטומטית בהרצה הראשונה ונשמר ב-
  `.env.documents-test` — קובץ שמוחרג מ-git. **לא קשור לסיסמת ההתחברות.**
- מוזרק ללקוח כ-`VITE_DOCS_API_KEY` בסביבת הבדיקה בלבד, כך שאין צורך בהזנה.
- כל בקשה בלי המפתח: 401 לכל הפעולות. מפתח ה-service לא קיים בסביבה הזו כלל.
- **מגבלה מתועדת:** סוד משותף ≠ הזדהות משתמשים. אין זהות פר-משתמש, ביטול
  הרשאה פרטני או תפוגה. מספיק לשלב הניסיון; לייצור רב-משתמשים נדרש
  Supabase Auth או שווה-ערך (שלב נפרד).

## בדיקות אוטומטיות

```powershell
# 52 בדיקות לוגיקה על הפונקציה האמיתית מול DB מדומה בזיכרון:
node --import ./scripts/mock-supabase-register.mjs scripts/test-documents-e2e.mjs

# 36 בדיקות חיות: HTTP אמיתי, קבצים אמיתיים על הדיסק, שרת אמיתי:
node scripts/test-documents-live.mjs
```

מכוסה: הרשאות לכל פעולה, העלאה+צפייה בייט-בייט, כפילות לפי hash כולל שתי
העלאות במקביל, token העלאה חד-פעמי, כישלון העלאה בלי רשומת רפאים, מסמכים
שונים באותו סכום, חשבונית+קבלה כשני מסמכים שאינם כפילות (וכפילות אמיתית
שכן מסומנת), עריכה/אישור/סינון, ארכיון ושחזור ללא מחיקה לצמיתות, חסימת
גישה ישירה לקבצים, ועמידות הנתונים על הדיסק.

## מעבר עתידי ל-Supabase אמיתי

הפונקציה עצמה לא שונתה — היא עובדת מול supabase-js הרגיל. כשיהיה פרויקט
Supabase לבדיקה/ייצור: מריצים את `db/migrations/001_documents.sql`, מגדירים
`VITE_SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` ו-`DOCS_API_KEY` (אקראי חדש)
ב-Netlify — והכל עובד ללא שינוי קוד.
