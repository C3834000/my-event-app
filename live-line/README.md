# קו חי: ניהול פעילות טלפונית בשידור חי

מערכת לניהול חדר ועידה של **ימות המשיח** מהמחשב, עד 250 משתתפים ויותר.

- **המנחה** מדבר מהטלפון וכולם שומעים אותו.
- **מסך הניהול במחשב** מאפשר:
  - לראות מי מחובר, בשמו (לפי הרשמה מראש).
  - להשתיק או לפתוח מיקרופון למשתתף אחד או לכולם.
  - לראות ידיים מורמות ולהוריד אותן.
  - להוציא משתתפים מהקו.
  - **טריוויה:** פותחים שאלה, המשתתפים מקישים 1–4 בטלפון, והתשובות מופיעים בזמן אמת. כשסוגרים את השאלה הניקוד מצטבר לטבלת המובילים.
- **דף הרשמה ציבורי** לכל אירוע: שם וטלפון, כדי שהמנחה יראה שמות ולא רק מספרים.

> התיקייה הזו **עצמאית לגמרי**. היא לא נוגעת במערכת האירועים הראשית, לא משתמשת בקוד שלה ולא משתמשת במסד הנתונים שלה. היא נפרסת כאתר Netlify נפרד.

---

## איך זה עובד

```
מאזינים ──חיוג──► ימות המשיח (חדר ועידה) ◄──טלפון── המנחה
                        ▲
                        │  GetIncomingCalls / CallAction  (מפתח API מוגבל)
                        │
   מסך המנחה ──► netlify/functions/api.mjs ──► Supabase (נרשמים, שאלות, ניקוד, יומן)
   דף הרשמה  ──┘
```

- המסך מתעדכן כל 2 שניות. השרת שואל את ימות המשיח מי בחדר, מה מצב המיקרופון של כל אחד, אם הרים יד ומה הקיש.
- **הטריוויה** מבוססת על יכולת מובנית של ימות המשיח: כל ספרה שמשתתף מקיש בתוך חדר הוועידה נשמרת אצלם (`survey`).
  - כשפותחים שאלה, המערכת מאפסת את ההקשות של כולם.
  - בזמן שהשאלה פתוחה היא קולטת את ההקשה האחרונה של כל משתתף, כך שמותר להתחרט עד הסגירה.
  - כשסוגרים את השאלה, המערכת מחשבת ניקוד ומאפסת שוב.
- הזיהוי בשם נעשה לפי מספר הטלפון של המתקשר, מול רשימת הנרשמים לאירוע הפעיל.

## הקמה (פעם אחת)

### 1. ימות המשיח: הגדרת שלוחות
בממשק הניהול של ימות המשיח יוצרים שתי שלוחות. המספרים כאן הם דוגמה.

**שלוחה 1: חדר הוועידה למאזינים** (`ext.ini` של שלוחה 1):
```ini
type=confbridge
title=קו חי
conf_bridge_type=listen
```
- `listen` פירושו שהמאזינים **לא יכולים לבטל השתקה בעצמם**. רק המנחה, מהמסך, יכול לפתוח להם מיקרופון.
- **אסור** להגדיר `confbridge_block_digits=yes`, כי ההקשות נחוצות לטריוויה.

**שלוחה 9: כניסת המנחה** (מומלץ מספר לא צפוי):
```ini
type=confbridge
title=כניסת מנחה
conf_bridge_type=admin
conf_bridge_folder_to_play=1
password=<קוד ארוך שרק המנחה יודע>
```
המנחה מחייג, נכנס לשלוחה 9 ומקיש את הקוד, וכך פותח את החדר שבשלוחה 1.

> את ההגדרות האלה כדאי לבדוק מול התיעוד או התמיכה של ימות המשיח, כי שמות ההגדרות עשויים להשתנות. לשאלות: https://f2.freeivr.co.il

### 2. ימות המשיח: מפתח API מוגבל (חשוב לאבטחה)
באתר הניהול: **אבטחה ← ניהול מפתחות גישה** (חומת האש).
1. יוצרים מפתח חדש.
2. ב**הגבלות שירותים** מאפשרים **רק** את `GetIncomingCalls` ואת `CallAction`.
3. ב**כללי חומת אש** מגדירים את ברירת המחדל כ**חסום**, ומוסיפים כלל שמאפשר רק את שני השירותים האלה.
4. את המפתח שומרים בצד לשלב 5.

כך, גם אם המפתח ידלוף, אי אפשר יהיה לשנות בו הגדרות, למחוק קבצים, להעביר יחידות או לראות דוחות.

### 3. Supabase: פרויקט נפרד
1. יוצרים פרויקט **חדש** ב-Supabase. לא את הפרויקט של מערכת האירועים.
2. **SQL Editor** ← מדביקים את התוכן של `supabase/schema.sql` ← מריצים.
3. **Project Settings ← API**: מעתיקים את `Project URL` ואת המפתח `service_role`.

כל הטבלאות נעולות (RLS ללא הרשאות). הדפדפן לא יכול לגשת אליהן. רק השרת ניגש, עם מפתח ה-`service_role`.

### 4. יצירת סיסמת מנהל ואימות דו-שלבי
במחשב שלכם, בתוך התיקייה `live-line`:
```bash
npm install
```
```bash
npm run setup-admin
```
- בוחרים סיסמה של 12 תווים לפחות.
- הסקריפט מדפיס ערכים להעתקה לשלב 5, ומפתח להוספה ל-Google Authenticator או Microsoft Authenticator.

### 5. Netlify: אתר חדש
1. **Add new site ← Import from Git** ← אותו מאגר.
2. **Base directory:** `live-line`. ההגדרות האחרות נקראות אוטומטית מ-`live-line/netlify.toml`.
3. **Site settings ← Environment variables:** מוסיפים את המשתנים מ-`.env.example`:

| משתנה | מה זה |
|---|---|
| `YEMOT_API_KEY` | המפתח משלב 2 |
| `YEMOT_CONF_ROOM` | מספר שלוחת חדר הוועידה (בדוגמה: `1`) |
| `LL_SUPABASE_URL` | מ-Supabase |
| `LL_SUPABASE_SERVICE_ROLE_KEY` | מ-Supabase. **לעולם לא בקוד** |
| `LL_ADMIN_PASSWORD_HASH`, `LL_TOTP_SECRET`, `LL_SESSION_SECRET`, `LL_SESSION_VERSION` | משלב 4 |

4. Deploy. מסך הניהול נמצא ב-`https://<האתר>/admin`.

## שימוש ביום האירוע
1. **אירועים:** יוצרים אירוע ← "הגדרה כפעיל" ← "קישור הרשמה". את הקישור שולחים למשתתפים.
2. **נרשמים:** כאן רואים מי נרשם. אפשר להוסיף ידנית, לייצא לאקסל ולמחוק.
3. המנחה מתקשר לשלוחת המנחה, והחדר נפתח. הנקודה הירוקה בראש המסך נדלקת.
4. **שידור חי:**
   - כרטיס **צהוב** הוא יד מורמת. המשתתפים מרימים יד בהקשה על `*2`.
   - כרטיס **ירוק** הוא מיקרופון פתוח.
   - "השתקת כולם" משתיקה מיד את כל המשתתפים.
5. **טריוויה:**
   - מוסיפים שאלות מראש. המנחה מקריא את השאלה ואת התשובות.
   - "פתיחה": המשתתפים מקישים 1–4, והגרף מתעדכן.
   - לחיצה על מספר התשובה הנכונה סוגרת את השאלה ומוסיפה ניקוד.
6. אחרי האירוע: **נרשמים ← "מחיקת כל הנרשמים"**, לשמירה על פרטיות המשתתפים.

## אבטחה: מה כבר מובנה

| שכבה | מה נעשה |
|---|---|
| כניסה | סיסמה מוצפנת (scrypt) **ו**קוד מאפליקציית אימות (TOTP). אין "שכחתי סיסמה". |
| ניחוש סיסמה | 5 ניסיונות ל-15 דקות מכל כתובת, ו-30 בסך הכול. כל כישלון נרשם ביומן. |
| סשן | עוגייה חתומה `HttpOnly` / `Secure` / `SameSite=Strict`, תקפה ל-8 שעות. העלאת `LL_SESSION_VERSION` מנתקת את כולם מיד. |
| CSRF | כל פעולה דורשת כותרת ייעודית ובדיקת מקור (Origin). |
| ימות המשיח | מפתח שמוגבל לשתי פקודות. השרת שולח רק 5 פעולות מוגדרות מראש, ורק למשתתפים שנמצאים כרגע בחדר. **את המנחה אי אפשר להשתיק או להוציא מהמסך.** פתיחת מיקרופון ליותר מ-30 משתתפים דורשת אישור. |
| מסד נתונים | פרויקט נפרד. RLS נעול. המפתח קיים רק בשרת. |
| דף הרשמה | ולידציה, מלכודת בוטים, 8 הרשמות לשעה מכל כתובת, תקרה של 1000 נרשמים לאירוע, ודרישת הסכמה. |
| דפדפן | CSP קשיח (בלי סקריפטים חיצוניים), HSTS, חסימת הטמעה במסגרת (iframe), `noindex`. |
| פרטיות | כתובות IP נשמרות רק מוצפנות. מספרי הטלפון מוסתרים חלקית כברירת מחדל. ייצוא CSV מוגן מהזרקת נוסחאות. |
| יומן | כל פעולה (השתקה, הוצאה, שאלה, כניסה) נרשמת עם זמן. |

**מה עליכם לעשות בנוסף:**
- להפעיל אימות דו-שלבי בחשבונות **Netlify, GitHub, Supabase וימות המשיח**.
- לא לשתף את הקישור `/admin` ולא לשמור את הסיסמה בדפדפן במחשב משותף.
- בימות המשיח: לתת קוד ארוך לשלוחת המנחה, ולשקול סינון לפי מספר הטלפון של המנחה.
- להחליף סיסמה מדי פעם: מריצים שוב `npm run setup-admin`, מעדכנים את הערכים ב-Netlify ומעלים את `LL_SESSION_VERSION`.

## מגבלות ידועות
- **השמעת מוזיקה:** ל-API של ימות המשיח אין פקודה להשמיע קובץ לתוך חדר ועידה. כרגע המנחה משמיע מהטלפון שלו, למשל ברמקול ליד המחשב. מוזיקת המתנה לפני תחילת השידור אפשר להגדיר בשלוחה עצמה.
- **מתקשרים ממספר חסוי** לא יזוהו בשם. הם יופיעו כ"לא רשום", ועדיין יוכלו לענות ולצבור ניקוד.
- **תשובה בטריוויה** נקלטת לפי ההקשה האחרונה לפני הסגירה. מי שניתק באמצע שומר על התשובה שכבר נקלטה.
- **צירוף משתתף בחיוג יוצא** עוד לא נבנה. אפשר להוסיף בעתיד דרך `RunCampaign`.

## פיתוח ובדיקות (בלי קו אמיתי)
```bash
npm install
```
```bash
npm test
```
להרצה מקומית עם קו מדומה של 250 משתתפים, בשני טרמינלים:
```bash
LL_MOCK_PARTICIPANTS=250 npm run dev:api
```
```bash
npm run dev
```
נכנסים ל-http://127.0.0.1:5174/admin. הסיסמה והקוד מודפסים בטרמינל של `dev:api`.
